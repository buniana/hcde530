# Week 2 — Competency 2: Code literacy and documentation

## Observations

This week I focused on how **code literacy** and **documentation** show up when using AI-assisted tools to work with data and small scripts.

### Visualization and rapid prototyping

In class I built a **dashboard from a CSV file in about a minute**. That interactive way of visualizing data felt like a fun, hands-on path into using AI to generate code. I also got more comfortable with **vibe coding** and **rapid prototyping**: trying ideas quickly, seeing output, and iterating instead of getting stuck on syntax first.

### Documentation as a record

I learned that it matters to **keep a clear record of the project**—not only for myself later, but so someone else could open the folder and understand what to run and what each part does. **AI can help draft** README text and other notes, but the goal is still a human-readable trail of decisions and how to reproduce the work.

### Concrete practices that helped

- **Comments on functions:** I asked Cursor to add short comments above functions so I could grasp what each piece does **without reading a long block of code** first. That directly supports my code literacy: I can map behavior to structure before diving into details.
- **README updates:** I used help to **update my README** so the project is easier to explain and run for others.

### Git and version control

I experimented with **Cursor to answer questions about Git commits** and **managing code on GitHub**. That felt connected to documentation in a broader sense: commits and a remote repo are part of how work is preserved and shared.

### Challenges

**File organization** became harder as I added more Python scripts and CSV files. The list of files grows quickly; I may need to **group files into folders** manually so the project stays scannable.

### Where I want to grow next

For Competency 2 I made progress on reading code with support from comments and on project-level docs. Looking ahead, I also want to build strength in **other competency areas**, especially **APIs** and **data handling**, so I can connect small scripts to richer sources of data and more realistic workflows.
